Lab 1: Data Collection and Pre-processing

This project explores e-commerce transactions with a Jupyter notebook. It loads a CSV, profiles prices and cities, checks data quality, cleans transactions, creates coupon and date features, aggregates revenue by city, and exports cleaned data as CSV and JSON.

Project structure

Lab1/
├── README.md
├── requirements.txt
├── Data/
│   ├── Ecommerce_transactions.csv           # input data (required)
│   ├── Ecommerce_transactions_backup.csv    # created by the notebook
│   ├── cleaned_transactions.csv             # created by the notebook
│   └── cleaned_transactions.json            # created by the notebook
├── Notebooks/
│   └── lab1_data_collection(3).ipynb
└── Src/
    └── Profiling.py                         # must define profile_transactions(data)

Only the notebook was supplied with this README. Add the input CSV and Src/Profiling.py before running all cells; the backup and cleaned outputs are generated during execution. The helper should accept a pandas DataFrame and profile transaction prices and unique shipping cities.

Requirements and virtual environment

Install Python 3.10 or newer and use a terminal at the Lab1/ root:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --user --name lab1-venv --display-name "Python (Lab 1)"
python -m jupyter lab

On Windows PowerShell, activate with .venv\Scripts\Activate.ps1 instead of source .venv/bin/activate. Open the notebook under Notebooks/, select the Python (Lab 1) kernel, and run cells in order from a notebook working directory of Notebooks/.

Path correction: The first CSV loading cell currently uses ../data/Ecommerce_transactions.csv, while later cells use Data/. On case-sensitive systems, change the first cell to pd.read_csv("../Data/Ecommerce_transactions.csv"). The profiling import expects ../Src/Profiling.py. If your notebook server uses the project root as its working directory, adjust these relative paths accordingly.

Execution note: The notebook intentionally edits the input CSV to add five practice errors and creates a backup before that edit. Its existing transactions variable is loaded before the edit, so subsequent cleaning works on the earlier in-memory data unless you reload the CSV. Keep the original input safe if you repeat the exercise.

Data source

Ecommerce_transactions.csv is synthetic data generated by ChatGPT for this exercise.Also, for codes and markdown text I used Chatgpt. The notebook adds intentional data-quality errors for cleaning practice.
